CAPITALEX DRIVER — V4 / ASSINATURA DE R$ 25,95 POR MÊS

STATUS DA ENTREGA
Código preparado e testes automatizados aprovados. Não foi publicado no seu
Netlify e nenhuma cobrança real foi ativada. Faltam as contas de serviços,
as variáveis de ambiente e os testes integrados descritos abaixo.

O QUE MUDOU
- Entrada/cadastro por código de e-mail: sem senha armazenada pelo aplicativo.
- Sessão em cookies HttpOnly, Secure e SameSite; tokens não vão ao localStorage.
- Registros financeiros no Supabase, separados pela identidade confirmada.
- Mensalidade fixa de R$ 25,95; checkout hospedado pela Stripe.
- Verificação de identidade e assinatura no servidor para ler/salvar o painel.
- Área Minha assinatura, cancelamento pelo portal e exportação dos próprios
  registros mesmo quando a assinatura não está ativa.
- Proteção contra gravações simultâneas e cópia da versão anterior no banco.
- Proteções existentes de importação, lixeira, gráficos e relatórios mantidas.

COMO FUNCIONA A COBRANÇA
O checkout usa cartão e renovação mensal automática. O servidor confere que o
preço configurado é BRL 2595 centavos, mensal, intervalo 1. Não aceita um preço
fornecido pelo navegador. Cupons e teste grátis não estão habilitados.

A cada consulta da conta e leitura/gravação do painel, o backend consulta a
Stripe diretamente. Exige plano correto, assinatura ativa, período vigente e
fatura paga de pelo menos R$ 25,95. Retornar do checkout NÃO libera o acesso.
Pagamentos pendentes, assinaturas vencidas ou em atraso bloqueiam o painel.
Cancelamento no fim do período mantém o acesso até o término já pago.

Esta implementação não depende de webhook: consulta o estado atual no provedor.
Isso evita autorizações baseadas em notificações antigas, mas adiciona consultas
e latência. Se a Stripe ficar indisponível, o painel não libera novas operações.
Uma futura otimização pode usar webhooks assinados com reconciliação periódica.
Reembolsos exigem também encerrar a assinatura no painel Stripe conforme sua
política; esta versão não faz revogação automática apenas pelo reembolso.

1. CONFIGURAR O SUPABASE
- Crie um projeto dedicado. Guarde as credenciais fora dos arquivos públicos.
- Abra SQL Editor e execute database/setup.sql uma vez.
- Mantenha o schema public habilitado no Data API. As duas tabelas usam RLS e
  não concedem acesso a anon/authenticated; só o backend tem acesso.
- Habilite o provedor Email em Authentication.
- Configure Site URL com o domínio HTTPS final do Capitalex.
- Em Email Templates, altere Magic Link para mostrar o código:

  <h2>Seu acesso ao Capitalex Driver</h2>
  <p>Digite este código na página de entrada: <strong>{{ .Token }}</strong></p>
  <p>Se não foi você, ignore este e-mail.</p>

- Verifique também o modelo de confirmação de cadastro, se aplicável ao projeto.
- Configure expiração do código em 10 minutos, mantenha limites de tentativas
  e use SMTP próprio para enviar a usuários reais. O envio padrão de teste
  do Supabase não deve ser usado como serviço de produção.
- Copie Project URL, chave publicável/anon e service_role para as variáveis
  de ambiente da Netlify. Nunca coloque service_role no HTML ou JavaScript público.

2. CONFIGURAR A STRIPE PRIMEIRO EM MODO DE TESTE
- Crie produto Capitalex Driver, preço recorrente mensal de R$ 25,95 em BRL.
- Quantidade fixa 1, sem teste grátis, cupons ou cobrança por consumo.
- Copie o identificador price_... e a chave secreta sk_test_... .
- Ative o Customer Portal: permitir atualizar o cartão e cancelar no fim do

- Use o ambiente de teste para validar o fluxo antes de trocar para produção.

  cadastre o preço no modo real e troque as duas variáveis.
- Tarifas do provedor e custos de hospedagem/banco são separados da mensalidade.

3. PUBLICAR NA NETLIFY
Este ZIP agora tem código de servidor. Arrastar apenas public/ para o Netlify
ou abrir index.html no computador NÃO publica as funções necessárias.

- Extraia o ZIP e coloque o projeto inteiro num repositório conectado à Netlify,
  com netlify.toml na raiz, ou faça deploy com Netlify CLI compatível.
- A configuração usa public como pasta publicada, netlify/functions para as
  funções e Node 22. Não há dependências npm de execução.
- Configure as seguintes variáveis para as Functions no ambiente de produção:

  APP_URL                         https://seu-dominio-final
  SUPABASE_URL                    URL do projeto
  SUPABASE_ANON_KEY               chave publicável/anon
  SUPABASE_SERVICE_ROLE_KEY       chave service_role privada
  STRIPE_SECRET_KEY               chave secreta de teste/produção
  STRIPE_PRICE_ID                 identificador do preço correspondente
  RATE_LIMIT_SECRET              segredo aleatório com 32 caracteres ou mais

- Gere RATE_LIMIT_SECRET com um gerador criptográfico, por exemplo:
  node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
- Não envie esse resultado pelo chat. Guarde diretamente na Netlify.
- APP_URL deve corresponder exatamente ao domínio usado no navegador; previews
  com outro domínio precisam de configuração própria e contas de teste.
- Faça novo deploy após configurar as variáveis. Abra a URL HTTPS publicada.
- Nunca mova server/, database/, tests/ ou .env para dentro de public/.

4. TRAZER OS DADOS DA V3
Antes de substituir a versão antiga, entre nela no MESMO navegador onde estavam
os registros e baixe Perfil e backup > Baixar backup.
Depois, na conta assinante da V4, use Perfil e backup > Restaurar arquivo.
A importação é explícita: não associa automaticamente dados locais a uma conta.
O limite atual de importação é 950 KB; limite da requisição ao servidor: 1 MB.
Se o arquivo for maior, mantenha o backup e adapte o armazenamento para registros
individuais antes de migrar. Não edite ou descarte o backup original.

LIMITES E OPERAÇÃO
- Os 20 testes incluídos usam respostas simuladas de Supabase e Stripe. Não
  substituem o teste integrado com seus serviços configurados.
- O SQL está preparado, mas não foi executado em um banco seu nesta entrega.
- O navegador de revisão não conseguiu acessar a prévia local; validação visual
  da nova tela no navegador e em dispositivos continua pendente.
- Não é uma auditoria independente nem garantia de segurança absoluta.
- Registros são transmitidos/guardados em Supabase; cobrança em Stripe. Configure
  sua política de privacidade, termos e identificação/suporte antes de vender.
- Programe backups do banco além da cópia anterior por conta. Uma cópia anterior
  ajuda a desfazer erro, mas não substitui backup externo e restauração testada.
- O painel é online. Esta versão não promete funcionamento offline.
- Novos registros não ficam no localStorage. Backups JSON baixados não são cifrados.
- Arquivos estáticos são públicos por natureza; a proteção efetiva está na API
  e nos dados da conta. Remova links públicos de versões antigas distribuídas
  gratuitamente se não quiser continuar oferecendo essa versão local.
- Não foi configurado pagamento por Pix nem boleto recorrente nesta entrega.
